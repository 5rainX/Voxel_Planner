# P2.1 Straight Twist Geometry

The fixed-version GitHub source comparison, independent quaternion checks and
measured numerical errors are recorded in [P2.1 cross-validation](fine_planner_p2_1_cross_validation.md).

`SegmentType::STRAIGHT_TWIST` extends the P1 Fine Planner interface. Its centerline is the exact straight segment from `start` to `end`. `twist_length` must equal that chord length in voxel units. The segment supplies unit `twist_start_normal` and `twist_end_normal`, both perpendicular to the centerline tangent, plus a signed `twist_angle_rad` and `twist_profile` (`LINEAR` or `SMOOTHSTEP`). The binormal is always `tangent × normal`, giving a right-handed `t/u/v` frame. Positive angles follow the right-hand rule about the direction from start to end. The start normal rotated by the signed total angle must match the end normal. Zero angle is valid.

At normalized distance `s` in `[0,1]`, LINEAR uses `angle(s) = total_angle × s`; SMOOTHSTEP uses `angle(s) = total_angle × (3s² - 2s³)`. The normal rotates around the fixed tangent by this angle, and the binormal is recomputed from the tangent and rotated normal. The complete twist occupies the full segment length. `maximum_sample_spacing` limits centerline spacing and `maximum_twist_step_rad` limits the angle change between samples. These are numerical sampling controls, not manufacturing standards.

The caller supplies `width`, `thickness`, `minimum_twist_length` and `maximum_twist_rate_rad_per_voxel`. A zero minimum length or maximum rate disables that particular manufacturing constraint. The peak angular rate is `|angle|/length` for LINEAR and `1.5 × |angle|/length` for SMOOTHSTEP. No industry threshold is assumed. The separate `GeometryValidator` checks these parameters, exact sampled position and frame evolution, endpoint frames and right-handed orthogonality. SDF clearance uses the section's enclosing half diagonal plus safety margin at sampled positions. This remains a conservative sampled check, not continuous swept-volume collision proof.

The Fine Planner owns its orientation samples. `optimizer::PoseTrajectory::recomputeFrames()` derives normals from position and would erase a twist; the P2.1 geometry and export do not call it. The existing optimizer and coarse planner interfaces remain unchanged.

Native `reference_geometry_v1` export retains ordered `reference_centerline` and `reference_poses` with `orientation_valid=true`. A twist segment adds `twist_start_normal`, `twist_end_normal`, signed `twist_angle_rad`, `twist_length_voxel`, `twist_profile` and `peak_twist_rate_rad_per_voxel`. The native export also records `section_width_voxel` and `section_thickness_voxel`; the Python validator binds them to source request arguments when present. Older native records without these optional fields remain readable. The Python Reference V1 validator checks the frame evolution independently, and Dataset V1 consumes the sourced normals for theta labels. Dataset V1 masks theta outside its existing ±π/2 target range and masks every node of a native twist whose total angle exceeds that range, since principal per-node angles cannot represent the cumulative turn. The native reference retains the actual signed angle and all sampled orientations. Historical TXT sidecars and data are unaffected.

The C++ Fine Planner test covers zero, positive and negative 90-degree angles, an arbitrary nonzero angle, both profiles, endpoint and rate failures, dimensions and sampled SDF clearance. `test_twist_reference_integration` checks the exported signed angle and nonzero theta through Reference V1, Dataset V1 and their validators.
